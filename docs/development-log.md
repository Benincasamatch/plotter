# 开发日志

## 2026-10-21

### 已完成：按串口保存设备配置

- 设备名称、控制器类型、XY 反转及对调、纸张起点、抬落笔 Z、手动 Z 速度、绘图及移动速度、微动参数组成设备档案，保存到服务端，跨浏览器共享。
- 在当前控制端内切换串口时，先保存旧设备档案，再恢复新设备档案；保存失败不切换。切换后旧预览和原点确认失效。
- 任务生成、手动抬落笔、笔状态识别、正常完成及终止回位均使用设备 Z 配置。执行前核对任务对应的端口与控制参数。
- 支持原奎享 GRBL 核验模式与通用 GRBL 模式；其他协议、舵机控制方式仍需单独适配。Z 参数须按设备实际校准，软件坐标反馈不代表绝对位置传感器。
- 已部署至现有网页及 Windows 控制服务。128 项 Python 测试、C++ 控制端测试、浏览器双端口档案切换及正式页面检查通过；自定义正负 Z 已通过模拟验证，尚不能替代每台机器的实物校准。

### 待开发：一个前端管理多个独立控制端

用户希望在同一个前端切换查看和操控两台写字机：一台连接 Windows 控制端，另一台连接树莓派控制端。切换所查看的设备时，另一台已启动的任务应继续执行，两台可以同时书写。

现状：树莓派已有独立 C++ 控制服务，部署及接口验证已完成；正式网页后端仍只有一个控制端地址。当前设备档案按串口区分，只覆盖同一控制端内的串口切换，尚未实现 Windows／树莓派控制端选择，不能将其描述为已支持多机并行管理。树莓派上的控制端还需同步支持设备档案协议。

后续方案：

1. 增加服务端控制端注册表，用稳定 `controller_id` 管理地址、名称与鉴权信息；浏览器通过业务后端操作，令牌不下发前端。
2. 用 `(controller_id, port)` 标识设备，迁移现有按端口保存的档案，避免不同主机上的相同端口名冲突。
3. 前端增加设备选择器，显示“Windows 写字机／树莓派写字机”的连接、运行、进度、ETA 与异常状态，并明确当前操作目标。
4. 所有连接、预览、检查、开始、暂停、继续、终止和手动动作明确绑定设备；任务缓存、原点确认与 ETA 按设备隔离，拒绝旧页面或过期响应将指令送错机器。
5. 切换查看目标不自动断开、暂停或终止其他设备。每台控制服务独立持有串口和任务工作线程；每个控制实例仍只管理一个活动串口。
6. 确认业务后端到树莓派的可达路径。不同网络时配置受控的隧道或组网；不能假定服务器能直接访问树莓派局域网地址。
7. 用两个独立模拟控制进程验证并行书写、切换、掉线、重启及配置隔离，再进行真机验收。
