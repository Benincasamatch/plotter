## 行为

“行间松紧”滑块的下限不再固定为 1 倍，而是由当前文字、字体组合、字高与仿真参数实时预测。低于该值时排版会压缩字形，因此滑块不能更紧；预测值与“最小可用行距 X mm”一起显示在排版提示里。

| 场景 | 结果 |
| --- | --- |
| 笔记 · 固定字高 | 滑块 `min` 为预测倍率，行距 = max(中,英) 字高 × 倍率 |
| 笔记 · 固定行数 | 同上；自动字高由行距与倍率反推，因此下限同时受 2–20 mm 字高限制 |
| 表格模式 | 不设下限，滑块保持 1–4 |
| 仿真开启 | 旋转、缩放、上下浮动都计入预算，下限相应抬高 |
| 无法满足 | `feasible=false`：提示要求减少行数、降低字高或增大边距，滑块不设下限以免卡死 |

### 预算与渲染共用一套度量

`prepare_notebook_tokens` 按“行内最高基线 + 最深下伸 − 2×基线起伏”压缩整行。预测用同一预算反解最小倍率，因此在下限处渲染不再缩放：

- 中文字符按中文字高的 `cjk_metrics` 参考高度换算，西文按 `metrics`；
- 取所有可能被选中的字体的墨迹外包（混排是逐字随机的，最坏情况必须覆盖）；
- 上标/下标按 `0.62` 倍嵌套再平移，符号与内置标点按各自构造；
- 仿真开启时，按旋转/缩放后的墨迹外包计算，再对行首尾各加一次上下浮动幅度；
- 公式保持自身高度，不参与行距预算。

## 接口

`POST /api/line-pitch`，请求体与 `/api/preview` 相同，返回：

| 字段 | 含义 |
| --- | --- |
| `min_ratio` | 滑块 `min`，已向上取整到 0.01 |
| `ratio` | 未取整的倍率 |
| `pitch_mm` / `ink_mm` | 该倍率下的行距与最坏墨高 |
| `drift_mm` | 为基线起伏预留的单侧空间 |
| `feasible` | 1–4 内是否存在同时满足字高、行数与墨迹的倍率 |
| `mode` / `line_sizing` | 回显请求模式；表格与旧请求返回 1 |

只读字体度量，不创建任务、不写磁盘。字符墨迹比例按字体文件 mtime 缓存。

## 兼容性

`/api/preview`、`/api/coordinate-preview` 的请求与响应不变；`/api/line-pitch` 为新增只读接口。用相同种子对比：

| 用例 | gcode |
| --- | --- |
| 纯文本笔记（固定行数/固定字高） | 逐字节一致 |
| 表格模式 | 逐字节一致 |
| 仿真开启 | 逐字节一致 |
| 含公式文档 | 逐字节一致 |

前端只在松紧低于预测下限时改写滑块值；旧排版预设缺少 `lineLooseness` 时仍按原公式推导，随后被下限夹住。

## 验证

服务端（`deploy/verify_line_pitch.py`）：

- 4 类文字 × 3 组仿真 × 2 种排版共 24 组：在下限处渲染缩放恒为 1，字高与行距不被压缩。
- 低于下限 0.05 倍时，渲染确实收缩到 0.958–0.974，说明下限不是随手放大的。
- 预测墨高与 24 个种子的实测最坏墨高一致（无仿真时完全相等；仿真时上界高出 ≤ 13%）。
- 表格模式、旧请求、空白文档返回 1；不可行布局返回 `feasible=false` 且倍率仍在 1–4。

浏览器（127.0.0.1:8091，真实字体 `blood8-2_kvenjoy_blood8`）：

- 载入时 `min=1.77`；改文字加入 `gjyq` 后升到 `1.86`，仅中文时降到 `1.01`。
- 开仿真后 `min` 从 `1.77` 升到 `2.08`，关闭后回落。
- 手动把滑块拖到 1.2 会被夹到 `min`；在该下限处生成预览成功，`中文 5.70 / 英文 5.70 mm`。
- 切到表格模式 `min` 回到 1，切回笔记模式重新预测。

### 同时修复的回滚助手

`deploy-git-rollback.ps1` 原先直接把 release 相对路径拼到仓库根：`Get-DeployedPath` 把 `README.md` 解析成仓库根的 `README.md`，而 `git status` 对不存在的路径不报错，所以干净检查永远通过、回滚必然以 `pathspec ... did not match` 失败（本次部署第一次失败即触发，8080 中断约 1 分钟）。

改法：新增 `-Base`（release 目录）与 `Get-GitPath`（用 `git rev-parse --show-toplevel` 转成仓库相对路径），并把 `\` 归一为 `/`。验证：`Assert-CleanSource` 对已修改文件报出全部四个文件；`../../README.md` 被越界检查拒绝；`Restore-CommittedFiles` 实际把四个文件恢复到 HEAD。
